# توقيع ثابت لتحديث التطبيق

النسخ السابقة استخدمت signingConfigs.debug داخل GitHub Actions، ما يولّد مفتاح تطوير جديدًا على جهاز بناء جديد. مفتاح التوقيع الخاص لا يمكن استخراجه من APK.

هذا التعديل يستخدم أربعة GitHub Actions repository secrets، ويحافظ على معرّف التطبيق com.shahin.daraya، ويرفع versionCode بحسب رقم تشغيل البناء. إذا كانت الأسرار ناقصة يفشل البناء قبل نشر APK؛ لا يوجد رجوع إلى توقيع التطوير.

## التفعيل مرة واحدة

1. افتح هذا الفرع داخل GitHub Codespaces أو جهاز فيه Java وGitHub CLI.
2. شغّل `bash android/setup-signing.sh`. يجب أن يكون الحساب مخوّلًا بإدارة أسرار المستودع. إن رفض GitHub الصلاحية، يلزم حساب المالك أو رمز يسمح بإدارة Actions secrets.
3. احفظ نسخة آمنة دائمة من مجلد daraya-signing-backup داخل مجلد المستخدم، قبل حذف Codespace. فيه مفتاح خاص وكلمة مروره. لا تضعه في مستودع GitHub ولا ترسله في المحادثة.
4. ادمج التعديل ثم تابع Build Shahin Android في Actions. لا تنشر APK قبل نجاح التحقق من توقيعه.

السكربت يعيد استخدام النسخة الاحتياطية الموجودة ولا يستبدلها تلقائيًا. لا تعِد تشغيله في جهاز جديد خالٍ من النسخة الاحتياطية إذا كانت الأسرار موجودة مسبقًا؛ استعد النسخة الاحتياطية أولًا.

الأسرار: ANDROID_KEYSTORE_BASE64، ANDROID_KEYSTORE_PASSWORD، ANDROID_KEY_ALIAS، ANDROID_KEY_PASSWORD.

إذا توفر مفتاح إصدار سابق محفوظ، استخدمه بدل توليد مفتاح جديد لتبقى التحديثات متوافقة مع ذلك الإصدار. إذا ضاع مفتاح التطوير السابق فقد يحتاج مستخدموه إلى حذف التطبيق مرة واحدة للانتقال إلى التوقيع الثابت؛ التحديثات التالية بنفس المفتاح لا تتطلب ذلك.

رابط التحميل الحالي يبقى صالحًا باستخدام وسم الإصدار القديم android-v1.3.0، مع تحديث عنوان الإصدار وملاحظاته إلى 1.4.0.

## التحقق

بعد إعداد الأسرار، ابنِ إصدارًا، ثبّته على جهاز اختبار، ثم ابنِ إصدارًا ثانيًا دون تغيير الأسرار وثبّته فوق الأول دون حذف. يجب نجاح التحديث وارتفاع versionCode وبقاء شهادة التوقيع نفسها. لم يُنفَّذ هذا الاختبار قبل توفير المفتاح.
