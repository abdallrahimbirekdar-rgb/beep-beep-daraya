# Website Android download entry

The header button beside More opens an accessible dialog with a disabled Google Play coming-soon panel and the existing signed APK release URL. The former footer APK banner and duplicated navigation link are removed. The entry is hidden for the native app (its existing ShahinAndroid user-agent marker) and installed standalone web apps. The new UI has Arabic, English and German text. It explains the browser-specific Android installation permission and how to turn it off after installing.

`android_download_daily` stores only a Damascus calendar date and an aggregate request count. No visitor/session IDs, account identifiers, IPs, device fields or persistent client storage are added. `record_android_download()` accepts no arguments and increments one daily counter atomically; admin accounts are excluded. Rapid accidental double activations within three seconds on the same page are suppressed without storage. This is not fraud-proof unique-person measurement. Direct APK URLs, Play Store downloads, blocked analytics requests, completed transfers and installs are not measurable by this counter. Downloading is never blocked when analytics fails.

The statistics dashboard shows total/today/7-day/30-day request counts with explicit limitations. `admin_android_download_stats()` returns aggregates only after checking the authenticated user against `platform_admins`. Table privileges are revoked for public clients, RLS is enabled, and public EXECUTE is revoked from both functions before scoped grants. Definer functions intentionally allow the narrowly scoped write and guarded admin aggregate read; no raw-table access is granted. No new Android permissions/SDK or Play Console form changes are included.

Verified: frontend tests for dialog/choices/permission text, native and standalone hiding, payload-free counting and double-click suppression, dashboard totals/error handling and localization; existing visitor reporting tests; asset build tests; live SQL transaction covering counter increment, admin exclusion, anonymous/nonadmin denial, grants, RLS and two-column data scope. SQL test changes roll back.

## Host-reported file downloads

The admin dashboard separately fetches the public GitHub release asset download_count for the uploaded souq-daraya.apk file. This runs only when an administrator opens statistics or requests refresh. Requests omit credentials and referrer, time out after eight seconds, and never include visitor identifiers. The host report and website request counters fail independently. Missing assets, rate limits, invalid counts and network failures show an unavailable state, never a fabricated zero. Zero is valid. Counts cover direct links and repeats; they do not prove completed transfers, installations or distinct people. Counts belong to the current asset and can reset when the Android release workflow replaces that asset. No historical host totals are inferred and no database or app collection changes are made.
